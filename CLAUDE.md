# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev       # start dev server at localhost:3000
npm run build     # production build (also runs TypeScript check)
npm run lint      # ESLint
```

There are no tests. `npm run build` is the primary correctness gate — TypeScript strict mode runs as part of it.

## Stack

- **Next.js 16** App Router — `app/` directory only, no `pages/`
- **React 19** — server components by default; add `"use client"` only when needed
- **TypeScript 5** strict mode — no `any`, ever
- **Tailwind CSS v4** — configured in `globals.css` via `@import "tailwindcss"`; there is no `tailwind.config.*` file
- **`@/` path alias** maps to the project root

## Architecture

This is a fully static site (SSG). All content is pre-rendered at build time — no client state, no API calls.

**Data flow:** `data/commands.ts` → components → rendered page. Nothing flows the other direction.

### Key design decisions

**Tailwind v4 CSS variables** — brand colours live as CSS custom properties in `app/globals.css` (`:root { --accent: #f7c948; ... }`). Reference them in Tailwind with the v4 shorthand: `text-(--accent)`, `bg-(--card)`. Do not use `text-[var(--accent)]` (longer form) or raw hex values in class names.

**Token colour classes** — command syntax highlighting uses `.token-kw`, `.token-flag`, `.token-str`, etc., defined in `globals.css`. These are not generated by Tailwind; they must stay in CSS. The same applies to `.ic-*` icon variant classes and `.card:hover` / `.section-title::after` pseudo-element rules.

**Dynamic class names** — `ic-${card.iconVariant}` in `CommandCard.tsx` is safe only because `.ic-*` classes are hand-written in CSS, not Tailwind-generated. Do not create new dynamic class patterns without adding them to `globals.css` first.

**`CommandBlock` style prop** — this component accepts an optional `style` prop so callers (`GitHubWorkflow`) can override its default bottom margin. This is intentional and the only place inline styles are permitted.

**Section rendering** — `app/page.tsx` maps over `sections` in a single loop. The `remote` section (`id === 'remote'`) receives a `<GitHubWorkflow>` card appended inside its grid. All other sections render their `cards` array only. Never reference sections by array index.

### Shared types (`types/index.ts`)

- `CommandCardDef` — card data shape (use this name; `CommandCard` is taken by the component)
- `CommandExample` — `{ label, tokens: CodeToken[][] }`
- `WorkflowStep extends CommandExample` — adds `step: number`
- `Section.cards` is `CommandCardDef[]`

## Conventions

- All content (commands, labels, token arrays) lives in `data/commands.ts` — never hardcode text in components
- Shared cross-component interfaces go in `types/index.ts`; component-local prop types are defined inline
- One component per file; default export only
- No `console.log`, no `eslint-disable`, no new dependencies without being asked
